# Web → Swift feature map

Source of truth: the web repo's **code**, read file by file (`public/js/app.js`,
`api.js`, `util.js`, `icons.js`, `gpx.js`, `itinerary.js`, `server/server.js`,
`server/seed-pois.js`), with README and CHANGELOG used only to spot where the docs
and code disagree (see the last section).

Legend — **Reuse**: port the logic 1:1 into `RoadTripCore` with tests whose expected
values come from the web code. **Rewrite**: same user-facing behaviour, native
implementation (MapKit / WeatherKit / SwiftUI / SwiftData). **Drop**: no iOS
counterpart.

## Where the README/CHANGELOG and the code disagree

1. **Motorcycle default range.** README (Features, "Vehicle garage") says 120 mi; `DEFAULT_VEHICLES` in `app.js` says 180 and CHANGELOG 0.4.0 records the bump. Decision: iOS uses **180**.
2. **Hourly horizon.** README says "hourly timeline within ~48 h"; `HOURLY_HORIZON_H = 47` in `api.js`.
3. **"Timezone-aware ETAs" is display-only.** `fmtClockTZ` formats in the stop's zone, but `nextResumeEpoch` builds the resume time with `Date.setHours` in the **browser's** zone and `departureEpoch` parses the `datetime-local` value in the browser's zone. A trip from Denver resuming "08:00" after a night in Dallas resumes at 08:00 Denver time. iOS evaluates departure in the origin's zone and resume in the stop's zone. Tests document this as an intentional deviation.
4. **Two-phase flow claim.** README: "forecast calls are spent only on the chosen route". `generateBriefing` loops over **every** route and briefs them all (CHANGELOG 0.4.0 "All routes briefed together"). iOS briefs the selected route by default and offers "Brief all routes" explicitly.
5. **README project layout** omits `public/js/itinerary.js`, which exists and is imported by `app.js`.
6. **Saved-trip contents.** README lists origin/vias/dest/departure/vehicle/range/multi-day; code also saves `routeIdx` and `stopEdits` (CHANGELOG 0.5.0 has it).
7. **POI dedupe wording.** Comments say "collapse anything within ~1 km"; the implementation is a grid key from `toFixed(2)` (≈1.1 km cells), so two nodes 50 m apart on either side of a cell boundary both survive. Ported as-is for parity and documented.
8. **Supercharger lookups** are described as "at every waypoint"; code skips the origin (`i > 0`).
9. **API-call counter** README lists ORS/OWM/NWS; code also counts OCM.
10. **CHANGELOG footer** has no `[0.5.0]` link and `[Unreleased]` compares against v0.4.0.
11. **Rest-area corridor** README says ~2.5 mi; code uses 4000 m (2.49 mi) — consistent, noted only because the brand radius 8000 m (4.97 mi) is described as "~5 mi".
